# حساباتي 2.0 — تسليم مرحلة التطوير 2026-10-17

**ملاحظة مهمة:** هذا فرع Flutter التطويري، وليس بديل HTML القديم.
لا يمكن تحديد نسبة إنجاز موثوقة (مثل 95%) قبل اختبارات فعلية ونجاح
الاعتمادات الخارجية. لا تفترض جاهزية الإنتاج بمجرد نجاح APK Debug.

## منفذ في الكود
- Flutter Android: الرئيسية والمعاملات، إضافة/تعديل/حذف/استبعاد، البحث والشهور
- إدارة الأقساط والدفعات وربط سحب موجود دون ازدواج
- تحليلات ستة أشهر، مقارنة شهرية، مصروفات حسب الفئات
- تقارير PDF شهرية عربية، متعددة الصفحات مع المعاملات المستبعدة
- استيراد SMS من ملفات TXT/CSV/JSON مع مراجعة وفلترة OTP والتكرار
- صور إيصالات حتى 1 MB مع عرض وحذف
- تصنيفات مخصصة في الإعدادات والمحرر
- تصدير ICS للأقساط (لا يعني إشعارًا مضمونًا وقت إغلاق التطبيق)
- نسخ JSON احتياطية واستيراد بيانات HTML مع تأكيد وحفظ نقطة استعادة
- الوضع الداكن/الفاتح وتخزين التفضيل
- مسارات دخول الإيميل/Google واستعادة كلمة المرور عبر Deep Link في Android
- حسابات محلية منفصلة مشفرة، Supabase Auth، RLS، سحابة CAS، مزامنة آمنة
  بعد الحفظ واسترجاع تلقائي فقط للحساب المحلي الفارغ
- واجهة Premium تستعمل Google Play Billing، وتُعطّل الشراء إذا فشل
  تحقق السيرفر أو لم يتم تفعيل البنية الخلفية
- Edge Function للتحقق من اشتراك Google Play، وحجز بصمة التوكن لكل حساب
- Workflow مستقل لإنشاء AAB موقع باستخدام أسرار GitHub
- نسخ Release تتطلب تسجيل الدخول (REQUIRE_ACCOUNT=true)، Preview يسمح بالضيف

## وظائف تحتاج موافقات وإعدادات خارجية أو اختبار حقيقي
1. SMTP: امتلاك دومين وتوثيقه في Resend وربطه بمشروع Supabase.
   تسجيل الإيميل غير معتمد لحد وصول رسالة فعلية وتأكيدها.
2. Google OAuth: Client ID وClient Secret وإعداد
   Android deep-link `io.github.mohmoudtarek37spec.hesabaty://auth-callback`
   ضمن Redirect URLs المسموح بها في Supabase.
3. Google Play: حساب مطور صالح، اشتراك `hesabaty_premium_monthly`
   منشور في Internal Testing، Service Account مفوض في Play Console،
   ضبط Google API وتخزين JSON كمفتاح سرّي Supabase، ثم تفعيل
   GOOGLE_PLAY_BILLING_ENABLED=true فقط بعد التحقق على جهاز فعلي.
4. التوقيع: مفتاح upload signing + أربعة GitHub Actions Secrets،
   ثم تشغيل android-release.yml اليدوي وتجربة AAB على Play Console.
5. اختبارات جهازين: إنشاء حساب وGoogle/Password reset، تحميل ومزامنة،
   حالة عدم اتصال، تعارض نسخ وحقوق وصول RLS، وعدم فقد النسخ القديمة.
6. الإنجليزية في واجهات Flutter لم تكتمل. تنبيهات الأقساط في الخلفية
   غير منفذة؛ تصدير التقويم بديل عملي لكنه يعتمد على استيراد المستخدم له.
7. مراجعة تكافؤ الشكل التفصيلي مع HTML، إمكانية الوصول، الأجهزة
   الصغيرة، سياسة الخصوصية وData Safety وصور المتجر.
8. إعداد مراقبة أخطاء الإنتاج وسياسات الاحتفاظ والإزالة قبل الإعلان العام.
9. يجب حفظ المفاتيح السرية خارج GitHub؛ لا نضع keystore أو service_role
   أو Google API secrets في المستودع العام أو في التطبيق.

## اختبارات القبول الضرورية قبل اعتبار التطبيق مكتملًا
- مستخدم جديد يسجل بإيميل غير تابع لفريق Supabase، ويصل رمز التأكيد.
- تسجيل حساب Google جديد وربطه بصورة آمنة عند تطابق إيميل موثق.
- فقد الهاتف: تسجيل الدخول على هاتف آخر يرجع نفس المعاملات والأقساط.
- الكتابة على هاتفين بالتتابع لا تستبدل نسخة أحدث بصمت.
- استيراد نسخة HTML حقيقية بعد Backup موافق عليه، ومقارنة الإجماليات.
- SMS يحتوي OTP يُستبعد، رسائل مكررة لا تتكرر، مراجعة كل معاملة.
- التقارير PDF تعمل بالعربية على الهاتف، والإيصالات لا تكسر الحفظ السحابي.
- الاشتراك لا يمنح Premium قبل Google API verification،
  وتجربة الشراء والاسترجاع والإلغاء والتجديد والمراجعة بعد انتهاء الاشتراك.
- نسخة AAB الرسمية موقعة، تفتح وتعمل في Google Play Internal Testing.

**لا ننصح بحذف نسخة WebIntoApp القديمة أو الاعتماد على Preview ببيانات حقيقية
حتى اجتياز جميع اختبارات الحفظ والاسترجاع.**
